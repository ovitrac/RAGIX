SECTION 1

1. Saqqara in one minute

Saqqara is the part of RAGIX that reads documents. It turns PDF, Word, Excel, PowerPoint and Markdown files into one kind of object, a typed tree, and keeps on every node the exact place it came from: the page and position, the cell, the paragraph, the slide or the line. It then recognises the structures a human reader sees, such as sections, tables, header bands and label columns, using ordered rules that are written down and tested. Where those rules cannot decide, Saqqara does not guess: it abstains, and records where and why.

No language model runs anywhere in Saqqara. The trees it builds are stored in a single SQLite file and can be searched on a lexical lane and, if an embedding model is configured, on a dense lane, with every hit leading back to the nodes it came from. The RAGIX families built on it, from search probes to reading reports, cite those nodes.

At a glance, Saqqara is defined by four numbers.

0 Language-model calls
5 Formats read natively
6 RAGIX kernels
154 Propositions, each tested

1.1 The problem it solves

Most retrieval pipelines begin by flattening documents into strips of text. A table loses its rows and columns, a heading loses its place in the hierarchy, and a citation shrinks to a file name, at best a page. Layout models recover part of that structure by prediction, and they are good at it, but a prediction can be wrong without saying so, and the same file can read differently after a model or library update. For a quality, audit or regulatory reader, two questions then go unanswered:

THE TWO QUESTIONS

“Where exactly, in which document, on which page, in which cell, does this statement come from?” And: “If I run the reading again tomorrow, on another machine, do I get the same result?” Saqqara is built so that both have a precise answer, recorded with the reading itself.

1.2 The Saqqara answer in plain terms

Saqqara treats a document as an object before it treats it as text. It reads what the file actually contains, builds the tree from those observations with every observation accounted for, and only then lets analyzers add structure, each one marking what it inferred and how confident it is. Four principles follow, and each one is checked by the test suite.

Object before fragment
One tree per document, in the same vocabulary for every format: document, section, heading, paragraph, list, table, cell, figure, caption. Chunks for search are cut from the tree afterwards, and each one keeps the list of nodes it came from.
An exact citation on every node
Each node carries its source, its format, a chain of locators from the broadest to the narrowest (page then position, sheet then cell, slide then shape) and the name and version of the code that read it. Within a tree, that chain is a unique address.
Abstain rather than guess
Structure is recognised by ordered rules over closed vocabularies. When the evidence does not settle a case, the analyzer abstains, and the abstention is recorded with its place, its reason and the signals it saw. Nothing is filled in to look complete.
Reproducible by construction
Trees serialise to canonical JSON. Two builds from the same observations are byte-identical, and a rerun on the same files yields the same trees and the same root hash. A second hash covers the source bytes without their paths: moving a file leaves it unchanged, editing one changes it.

1.3 Who it is for

Saqqara serves three audiences. Product and engineering teams building retrieval or analysis on regulated documents get a reader whose output they can cite and replay. Quality, audit and compliance functions get readings that state what was read, what was refused and where the reader declined to decide. Architects choosing a document layer get a component that runs entirely on their own infrastructure, with permissive licences by default and no model to host. The rest of this sheet sets out what makes it different, what it can do, how it fits inside RAGIX, how it compares with Docling, and what was measured.

The guiding idea, in one line: a document is an object before it is a fragment — read it once, exactly, keep every citation, and let everything above cite the same nodes.
