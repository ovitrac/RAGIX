4. Saqqara inside RAGIX

Saqqara is not a separate product bolted onto RAGIX. It is a family of RAGIX kernels: the same kernel contract, registry and orchestrator, the same MCP server and the same run envelope as every other family of the platform. It is also the substrate that RAGIX's document families stand on. The tender family queries the store Saqqara builds, and the harvest family reports over the readings it makes. A document read once by Saqqara is available, with its citations, to every consumer above it.

The figure shows the four layers a request crosses. Every interface reaches the same kernels; the engine chains them by what each one declares it needs; Saqqara reads and indexes without any language model; and the families above consume what it provides.

4.1 Six kernels, one contract

Every RAGIX kernel declares a name, a stage, what it requires and what it provides, and implements one computation. The platform's kernel base runs it inside a common envelope: it validates the inputs, writes the output file, produces a summary and records which dependencies were resolved. Saqqara contributes six kernels to that contract.

4.2 Chained by what they declare

The registry discovers every kernel in the RAGIX package tree. It resolves a requirement first as a kernel name, then as a capability that exactly one kernel provides: two providers for the same capability is an error, never a silent choice. The orchestrator then orders the kernels by their declared needs, hands each one its producer's output, and writes down which kernel served each requirement. In the words of the code: "the day a second kernel provides document_tree, the record says which one served this run."

WHY IT MATTERS

A reader can be replaced, or a second one added, without touching anything that consumes its output — and every run states which one was used. Provenance does not stop at the page and the cell: it extends to the software that read them.

4.3 Four doors, one answer

MCP, for AI orchestration
The RAGIX MCP server registers four tools at start-up: koas_saqqara_run, _status, _index and _search. If their registration fails, the failure is logged and the server starts without them.
Command line, for automation
saqqaractl run | status | index | search, each with a --json output for scripts and pipelines. The command line and MCP return the same hits for the same query on the same store, a property the test suite checks (K7.16).
Python, for products
SaqqaraKernel().run(KernelInput(workspace, config)) returns the same envelope as any RAGIX kernel: data, summary, output file and the resolved dependencies.
The orchestrator, for chains
ragix-koas runs Saqqara stage by stage with the other families, from reading to indexing to the probes and reports that consume the store.

4.4 The families built on it

Two RAGIX families are defined as work over what Saqqara produces. The tender family runs its probes over a document store built by Saqqara: its probe kernel requires document_store, and its one way to obtain a tree is Saqqara's reader and analyzers. It adds its own fusion weights, boosts and filters on top of Saqqara's retriever, without copying it. The harvest library builds the Explorer's reports from its readings, field views, census and privacy marks; the Explorer's last kernel calls it. Each family carries its own tests: 141 test functions for tender, among them one that checks that adding the family moves none of Saqqara's pinned lists, and 301 for harvest.

4.6 How a product builds on Saqqara

Adservio's own document products use Saqqara through a small set of rules, and the same pattern serves any product built on RAGIX.

Pin one commit
Install RAGIX from an exact commit, not from a working tree, and refuse to start on a mismatch. The reading a product relies on is then the reading the tests certified.
Keep your records beside the store
Store the product's own records in a separate database, keyed by Saqqara's immutable identifiers: the source hash, the document and the node. Saqqara's store is read, never rewritten.
Invalidate on change
A document's identity in the store is the hash of its bytes, and a run's source_root covers those hashes without the paths. When a source is edited, both change, and every record derived from it is set aside until it is recomputed. When a file is only moved, neither changes.
Put the model above, not inside
Saqqara stays free of language models. A product that uses a model gives it bounded excerpts that carry Saqqara's citations, so every answer leads back to a node of the tree.
THE NET EFFECT

A document is read once, by tested code, at a known version, and every RAGIX family and every product above it cites the same nodes. The reading is shared; the interpretation stays with each consumer.
