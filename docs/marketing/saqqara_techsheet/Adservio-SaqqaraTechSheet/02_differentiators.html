2. What makes Saqqara unique

Many libraries convert documents to text or Markdown. Saqqara is distinguished by five design choices that hold together. Four of them are written as propositions in its specification and checked by its tests. The fifth, the absence of any language model, is a design rule: it is stated in the documentation and can be read in the dependencies. The table summarises the five; the pages that follow explain each in turn.

2.1 Provenance on every node

A Saqqara node never exists without its provenance: a node with an empty locator chain is refused at construction. The chain goes from the broadest unit to the narrowest, in the vocabulary of each format: page, then position for a PDF; sheet, then cell, row, column and merged range for a spreadsheet; paragraph, run or table cell for Word; slide, then shape for PowerPoint; line for Markdown. Each node also names the code that read it and its version, and can carry the hash of the source file. Within a built tree, a locator chain is a unique address, so a citation points to one node and only one.

WHY IT MATTERS

Search results, summaries and reports built on Saqqara inherit those addresses. A reviewer who questions a figure in a report can open the exact cell it came from, in the exact file, read by a known version of the code.

2.2 Rules that abstain rather than guess

Structure is recognised by analyzers that apply ordered rules and write only from closed vocabularies. Each one records whether a node was read (confidence 1.0) or inferred (below 1.0). When the evidence does not settle a case, the analyzer abstains, and the run's abstention register records the document, the analyzer, the place, the reason and the signals observed. A few examples from the specification:

  • Header bands of a table are recognised only when they are laminar; overlapping merged headers produce no band at all, and a band deeper than the configured cap is reported with the depth found.
  • A caption is bound to a figure by rules at stated confidence levels; two candidates at the same distance give an abstention, never a tie-break.
  • A lattice of drawn lines is not a table: it is routed as a table image at confidence 0.5, never promoted to rows and cells.
  • A page without a text layer is recorded as unread, never as empty; a document set in one uniform type size gets no promoted headings.

2.3 No language model inside

Reading, building and analysis are computation, start to finish. The only model Saqqara can call is the embedding model a user configures for the dense search lane, and with the default setting provider: none nothing is embedded and nothing leaves the machine. There is no network call except to that configured embedder, secrets are passed by reference, and the Explorer chain is tested under a socket guard that fails any network access. The practical consequence is simple: Saqqara runs on a laptop, a server or an air-gapped host, with no model to host, license or update.

2.4 One tree for every format

PDF, Word, Excel, PowerPoint and Markdown each have their own reader, but all of them produce the same node kinds through one builder, and the per-format differences are declared as data rather than scattered through code. Legacy .doc and .xls files are converted by LibreOffice, run headless without a shell, with a fresh profile, macro security at its strictest level, links not updated, and fixed size and time limits. The conversion is recorded in the provenance with the hashes of both files and the converter's version; Saqqara does not claim that the converted layout is identical to the original.

2.5 Reproducible and accounted for

Every reading can be replayed and every input can be reconciled with the output. The builder guarantees that each observation read from a file ends as exactly one node, one attachment or one counted drop, and the three totals add up to what was read. Trees serialise to canonical JSON, whose round trip is byte-identical. A run returns two roots, and the difference between them is deliberate.

merkle_root, over the trees
A Merkle root over the canonical JSON of every tree. A rerun on the same files at the same paths gives the same root, so a claim about a document can name the exact reading it was made from. Trees record their source path, so this root follows the path too.
source_root, over the bytes
A root over the hashes of the source files, with their paths left out. Moving a document does not change what it says, so the root stays; editing one changes it.

The core of these properties is set out in 154 propositions, each carried by a test. Another 34 extend the specification to boundary-aware field views (4), the Explorer (25) and legacy Office conversion (5). The specification also publishes its two known gaps. H1: the spreadsheet library drops an image it cannot decode while loading, so such a picture is neither read nor counted. H2: text drawn inside a PDF form object, such as the running header of a browser-printed page, is read twice and partly misplaced; body text is not affected. Each gap is documented with its cost and the route to closing it, rather than left for a user to discover.

THE NET EFFECT

A document read by Saqqara comes with its own audit trail: what was read and where, what was refused and why, where the reader declined to decide, and two hashes that let anyone check, later and elsewhere, that the reading is the same one.
